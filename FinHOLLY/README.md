# FinHOLLY — 온프레미스 금융 도메인 번역 파이프라인

한국어 → 동남아 5개 언어 금융 문서 번역을 **온프레미스(폐쇄망)**에서 수행하기 위한 번역 모델 학습·배포 파이프라인입니다. 금융기관 특성상 문서를 외부 API로 내보낼 수 없다는 제약에서 출발해, 사내 GPU 한 장으로도 학습·서빙이 가능한 경량 구조를 목표로 설계했습니다.

- **베이스 모델**: `facebook/nllb-200-distilled-1.3B`
- **언어쌍**: 한국어(`kor_Hang`) → 베트남어·인도네시아어·태국어·타갈로그어·미얀마어
- **핵심 아이디어**: 하나의 공유 인코더 위에 **금융 도메인 어댑터**와 **언어 어댑터**를 분리해서 얹는 조합형(composable) LoRA 구조
- **배포**: 어댑터 병합 → CTranslate2 int8 양자화 → CPU/단일 GPU 서빙

---

## 왜 이렇게 설계했는가

### 1. 온프레미스 제약
금융 문서는 개인정보·거래정보가 포함되어 상용 번역 API(외부 전송)를 쓰기 어렵습니다. 그래서 1.3B급 경량 모델을 골라 **사내에서 직접 학습·서빙**할 수 있게 했고, 배포 단계에서 int8 양자화로 용량과 추론 비용을 낮췄습니다.

### 2. 분리형(조합형) 어댑터
일반 번역 모델을 그대로 쓰면 금융 용어의 의미를 자주 틀립니다. 예를 들어 "청산", "모집", "사모" 같은 단어는 **금융 맥락**과 **일상 맥락**에서 번역이 달라져야 합니다.

이를 위해 두 종류의 LoRA 어댑터를 **독립적으로** 학습합니다.

- **도메인 어댑터**: 언어와 무관하게 "금융 의미"를 잡아주는 역할
- **언어 어댑터**: 각 목표 언어의 번역 품질을 끌어올리는 역할

둘을 분리했기 때문에, 새로운 언어를 추가할 때 언어 어댑터만 새로 학습하면 되고 도메인 지식은 재사용됩니다. 두 어댑터의 LoRA 설정(rank 16, `q_proj`/`v_proj`, fp16)을 통일해 나중에 조합·비교할 때 일관성을 유지합니다.

### 3. 대조학습으로 용어 의미를 잡는다
도메인 어댑터는 단순 지도학습이 아니라 **대조학습(contrastive learning, SupCon 스타일)**으로 학습합니다.

- 공유 인코더의 마지막 hidden state를 attention mask로 평균 풀링 → L2 정규화한 임베딩에 대조 손실을 겁니다. 이 임베딩이 "언어 무관 핵심 표현"이라, 여기에 손실을 걸어야 "용어 감각을 언어와 무관하게 학습"한다는 목적에 맞습니다.
- 같은 `(용어, 의미)`끼리는 가깝게, 같은 용어라도 의미(금융 vs 일상)가 다르면 멀어지게 당깁니다.
- 배치를 무작위로 짜면 같은 용어가 거의 안 겹쳐 대조 손실이 스킵되므로, **용어 단위로 예문을 몰아 담는 배치 샘플러**를 씁니다.

## 파이프라인 구성

세 노트북을 **순서대로** 실행하면 데이터 생성 → 어댑터 학습 → 배포까지 재현됩니다.

| 단계 | 노트북 | 하는 일 |
|------|--------|---------|
| 1 | `01_finance_data_generation.ipynb` | 금융/일상 이중 의미 문장쌍을 LLM(EXAONE 3.5·Groq)으로 생성하고, LaBSE 정렬 검증으로 저품질 쌍을 걸러 train/val/test로 병합 |
| 2 | `02_domain_adapter_training.ipynb` | NLLB에 LoRA를 붙여 대조학습으로 **금융 도메인 어댑터** 학습. 학습에 없던 용어(청산·사모·모집)로 일반화 성능 평가 |
| 3 | `03_language_adapter_myanmar.ipynb` | **미얀마어 언어 어댑터** 학습(다른 4개 언어도 동일 절차) → 도메인+언어 어댑터 병합 → CTranslate2 int8 변환 → FLORES-200 평가 |

> `03`은 미얀마어를 예시로 담았습니다. 나머지 언어(베트남·인도네시아·태국·타갈로그)는 목표 언어 코드만 바꿔 같은 절차로 학습합니다.

---

## 평가 방법

- **용어 의미 정확도 (도메인 어댑터)**: LaBSE로 "생성된 번역이 의도한 의미(금융/일상)의 정답 쪽에 더 가까운가"를 측정합니다. 금융 문장은 금융 의미로 제대로 번역됐는지, 일상 문장은 원래 의미를 유지하는지를 각각 봅니다.
- **번역 품질 (언어 어댑터)**: sacreBLEU로 held-out 세트 및 **FLORES-200** devtest 기준 점수를 측정합니다.
- **비교 기준**: 순정 NLLB(어댑터 미적용) vs 어댑터 적용을 같은 세트에서 대조합니다.

| 지표 | 순정 NLLB | +어댑터 |
|------|-----------|---------|
| 용어(금융) 정확도 | _(기입)_ | _(기입)_ |
| 비금융 유지율 | _(기입)_ | _(기입)_ |
| BLEU (FLORES devtest) | _(기입)_ | _(기입)_ |

> 표의 수치는 각 노트북 실행 결과로 채우면 됩니다.

## 기술 스택

- **모델/학습**: PyTorch, Hugging Face Transformers, PEFT(LoRA), NLLB-200-distilled-1.3B
- **데이터 생성**: EXAONE 3.5 (Ollama), Groq API
- **품질 검증**: LaBSE (문장 임베딩 정렬)
- **평가**: sacreBLEU, FLORES-200
- **배포**: CTranslate2 (int8 양자화)

## 실행 방법

노트북은 Google Colab(T4 GPU) 기준으로 작성되어 있습니다.

1. Google Drive에 `FinHOLLY/` 폴더를 만들고 아래처럼 데이터를 배치합니다.
   ```
   FinHOLLY/
   ├── data/                # 학습·평가 CSV (contrastive_train/val/test 등)
   ├── exaone_generated/    # 01 단계 생성 결과
   ├── domain_adapter_run/  # 02 단계 학습 산출물
   └── my_language_adapter_run/  # 03 단계 학습 산출물
   ```
2. `01 → 02 → 03` 순서로 실행합니다.
3. API 키(`GROQ_API_KEY`)는 Colab `userdata`(Secrets)에 등록합니다. **코드에 키를 하드코딩하지 않습니다.**

> 폐쇄망 환경에서는 Colab/Drive 경로를 사내 스토리지 경로로, Groq 호출을 사내 LLM으로 교체하면 됩니다. 최종 서빙은 외부 통신 없이 CTranslate2 int8 모델만으로 동작합니다.
